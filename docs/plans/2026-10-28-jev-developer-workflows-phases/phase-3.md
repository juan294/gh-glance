## CI acquisition and UI

`d` on Actions opens a standalone-only sidecar. Connected mode explains the limitation and offers the selected run's existing browser URL, with zero local GitHub or Jev calls. Bind the sidecar to host/repo/access partition/run ID/generation. Follow existing Actions setup lifecycle/admission/scope retirement (`index.mjs:19679`, `:19201`); do not store it in list caches or collector messages.

1. Fetch `GET /repos/{owner}/{repo}/actions/runs/{run_id}?exclude_pull_requests=true`, declared `detail:actions-run`. Validate ID, repository, attempt, head SHA, status/conclusion, updatedAt and same-host HTML URL. Pin attempt/SHA. If the response shows the selected row changed, show “Run changed; refresh Actions and reopen”; do not silently analyze a new attempt as the selected old row.
2. Fetch one `GET /repos/{owner}/{repo}/actions/runs/{run_id}/attempts/{attempt}/jobs?per_page=100&page=1`, declared `detail:actions-jobs`. Validate run ID/SHA and retain job ID, name, conclusion/status, URL and bounded steps. Attempt association comes from the endpoint, not an invented job.run_attempt field. Show total/loaded jobs and partial coverage if total_count or Link indicates more. No automatic pagination. Show failed/timed-out jobs first; canceled/running is not diagnosed failure.
3. `l` explicitly fetches only the selected failed/timed-out job's plaintext log through a controlled native HTTPS `GET /repos/{owner}/{repo}/actions/jobs/{job_id}/logs`, declared `detail:actions-job-log`, followed by at most one credential-free storage GET. No whole-run ZIP, `--paginate`, `gh run view --log-failed`, implicit retry or fallback acquisition. Retain local line numbers and completeness. Do not guess step-to-line associations; step metadata is separate. `Enter` opens the exact selected job on GitHub.

Bounds: two metadata endpoint operations per open, one log endpoint operation per `l`, one active generation, 100 jobs, 100 steps/job, metadata aggregate 2 MiB, captured log 1 MiB, 45-second metadata workflow deadline, 20-second log deadline, existing 2-second admission wait. Cap parsed retained fields and metadata responses, not just post-render rows. If output exceeds the capture cap, return oversize/unavailable and discard partial stdout as a completed log. Closing/switching scope aborts work but preserves child-close and durable settlement evidence. Ordinary list loading/freshness stays independent.

[GitHub workflow runs](https://docs.github.com/en/rest/actions/workflow-runs) and [workflow jobs](https://docs.github.com/en/rest/actions/workflow-jobs) document these endpoints. The job-log endpoint is a one-minute 302 link to plaintext, not the run ZIP. Actions read permission is required where applicable; existing authentication does not prove that permission. Per-step log routes and historical-attempt selection are deferred.

```text
@ openCiEvidence(selectedRun, scope) -> sidecar
pre: explicit standalone action; selected source identity captured
do:
  1. validate run identity through separately admitted metadata request
  2. parse one separately admitted attempt jobs page
  3. emit exact facts, coverage and selected-job log action
br: changed run -> refresh/reopen; user requests log -> separately admitted bounded transfer
fx: ephemeral evidence only; each dispatched operation settles its own receipt
fail: permission, admission or transport error -> safe retry or GitHub link
```
